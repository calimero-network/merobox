## `merobox cloud run WORKFLOW`

Start the workflow's cluster, run its steps, stop the cluster.

| Flag | Meaning |
| --- | --- |
| `--binary PATH` (also `--binary-path`) | merod binary (default: `MEROD_BINARY`, then `MEROD_V2_BINARY`, then `PATH`) |
| `--data-dir PATH` | Keep the cluster's state here instead of a temporary directory |
| `--logs` | Show the nodes' logs |

Exit codes: 0 passed, 1 a step failed, 2 the file is invalid (or not a
`backend: cloud-v2` workflow), 3 a port marked not applicable.

## `merobox cloud validate WORKFLOW`

Check a workflow without starting anything. Exits 1 when it is invalid.

## `merobox cloud port SOURCES... --out-dir DIR`

Port v1 workflows to cloud-v2 workflows; see [Port a v1 workflow](/guides/porting/).

| Flag | Meaning |
| --- | --- |
| `--out-dir DIR` | Where ported files go (required) |
| `--wasm-map FILE` | JSON: `{bundle path: {service or "": wasm path}}` for install/create steps |
| `--base-port N` | First file's cluster port base (default 2800; +10 per file) |

## v1's names

| Command | Same as |
| --- | --- |
| `merobox bootstrap run WORKFLOW` | `merobox cloud run WORKFLOW` (same flags; `--no-docker` is accepted and ignored) |
| `merobox bootstrap validate WORKFLOW` | `merobox cloud validate WORKFLOW` |
| `merobox run WORKFLOW` | `merobox cloud run WORKFLOW` (same flags; `--no-docker` is accepted and ignored) |

v1's node commands (`stop`, `nuke`, `logs`, `health`, `remote`, `group`,
`namespace`, and `run` as a node starter) are gone with v1's nodes: a run
starts and stops its own cluster (`--logs` shows its output, `--data-dir` keeps
its state), and organizations and teams are workflow steps.
