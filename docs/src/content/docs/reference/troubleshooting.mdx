title: Troubleshooting

---

**`merod not found`.** Build it from core's `release-v2` branch
(`cargo build -p merod`) and set `MEROD_BINARY`, or pass `--binary`.

**`not a release-v2 workflow (expected 'backend: cloud-v2')`.** The file is a
v1 workflow. [Port it](/guides/porting/) with `merobox cloud port`.

**A node exits or never answers `/health`.** Run again with `--logs` to see
`merod`'s output. Node `i` listens on `127.0.0.1:base_port+i`; another process
on one of those ports (another cluster with the same `base_port`) stops it from
starting. Give each concurrently running workflow its own `cluster.base_port`.

**`unresolved placeholder {{name}}`.** A step names a variable nothing set:
check the earlier step's `outputs` and the path it maps. When an output path is
missing, the error shows the result the step returned.

**An assertion fails on a placeholder.** In `assert` / `json_assert`, an
operand's `{{name}}` must be a variable set by `outputs` or `set`; a name that
resolves to nothing fails the statement rather than comparing as text.

**A step that needs `KV_STORE_WASM` (or another `{{env.NAME}}`).** The
variable is unset in the environment; see [Examples](/workflows/examples/) for
what each example needs.

**Inspecting state after a run.** Pass `--data-dir DIR`: each node's state is in
`DIR/node<i>` and is kept after the run.
