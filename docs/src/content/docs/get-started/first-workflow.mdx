A workflow is a YAML file with `backend: cloud-v2`, the cluster to start, the
accounts to sign up, and a list of steps.

```yaml title="hello.yml"
name: Hello, cluster
backend: cloud-v2
cluster: { nodes: 3, base_port: 2700 }   # node i listens on 127.0.0.1:2700+i
accounts: [alice]                        # signed up with her own passkey
steps:
  - name: Deploy kv-store
    type: deploy
    account: alice
    wasm: "{{env.KV_STORE_WASM}}"
    app_name: kv
    outputs: { app_id: appId }

  - name: Write
    type: call
    account: alice
    app: "{{app_id}}"
    method: set
    args: { key: greeting, value: hello }

  - name: Crash node 1
    type: kill_node
    node: 1

  - name: Read it back
    type: wait_for
    account: alice
    app: "{{app_id}}"
    method: get
    args: { key: greeting }
    equals: hello
    outputs: { greeting: result }

  - name: Check
    type: assert
    statements:
      - "equal({{greeting}}, 'hello')"
```

Check it without starting anything, then run it:

```bash
merobox cloud validate hello.yml
merobox cloud run hello.yml
```

What each piece does:

- **`outputs`** maps a variable to a path in the step's result; later steps
  read it as `{{app_id}}`. A whole-string placeholder keeps its type.
- **`account`** says who acts. Each account talks to its own node first
  (`accounts` order modulo the cluster's size) and falls over to the others, so
  a crashed node does not fail the step.
- **`kill_node`** ends node 1's process; `start_node` brings it back with its
  data.
- **`wait_for`** retries a view until it returns the value.
- **`assert`** checks statements over the workflow's variables.

The full format is in [Workflow YAML](/workflows/yaml/).
