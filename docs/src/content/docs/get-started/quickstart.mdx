merobox starts a release-v2 cluster of `merod` nodes, one process per node on
127.0.0.1, runs a workflow's steps against it as clients, and stops it.

<Steps>

1. **Install merobox.** It needs Python 3.9+ and a Rust toolchain, because
   `calimero-client-py` (its `CloudClient`) is built from source:

   ```bash
   git clone https://github.com/calimero-network/merobox.git
   cd merobox
   pip install -e .
   merobox --version
   ```

2. **Build `merod` and the kv-store app** from
   [core](https://github.com/calimero-network/core), branch `release-v2`:

   ```bash
   cargo build -p merod
   cargo build -p kv-store --target wasm32-unknown-unknown --profile app-release
   export MEROD_BINARY=$PWD/target/debug/merod
   export KV_STORE_WASM=$PWD/target/wasm32-unknown-unknown/app-release/kv_store.wasm
   ```

   merobox looks for `merod` in `--binary`, then `MEROD_BINARY`, then
   `MEROD_V2_BINARY`, then `PATH`.

3. **Run an example.**

   ```bash
   merobox cloud run workflow-examples/cloud-v2/kv-store-failover.yml
   ```

   It deploys a KV store, writes through a node crash, a frozen node and a
   restart, and checks every replica caught up. The exit code is 0 when the
   workflow passes, 1 when a step fails, 2 when the file is invalid and 3 for a
   port marked not applicable.

</Steps>
